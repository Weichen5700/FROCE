# 個股分析：以少數指標、ROCE 為核心的優化方向

日期：2026-10-15。依目前工作目錄的程式碼與既有測試分析；本文是設計建議，尚未變更產品行為。

使用者提供的原則是「以達爾文教的方式、少數指標、ROCE 為核心」。未提供書名、版本或原文，因此本文的流程、觀察期間及門檻建議不歸因於作者。

## 建議的判斷流程

資料可判讀 → 多年 ROCE 是否持續 → 現金流與負債有無待查原因 → 現價與獲利是否匹配 → 保存觀察理由。

主畫面保留三個問題：資本效率如何、獲利是否有現金流支持、價格對應什麼獲利假設。負債、流動性、資料缺漏以獨立提醒呈現，不用其他項目的高分抵銷。原有細項與總分可保留在展開區。

## 1. 讓 ROCE 成為主判斷，總分降為輔助

程式預設權重是 ROCE 40%、營業利益率 20%、ROE 15%、負債比 15%、流動比率 10%。這是程式預設，未查詢使用者資料庫目前儲存的自訂設定。ROCE 達 20% 後該項均為滿分。

總分可以排序，但不能直接表達「為什麼符合你的方法」。建議建立 ROCE 核心檢視，分開呈現核心條件與風險提醒；營益率用於解釋 ROCE，ROE 放補充資料，避免三種獲利比率共同決定主結論。負債比、流動比率不設跨產業通用的買進門檻。

依據：`RoceTool.Core/Calculators.cs:136-183`；`RoceTool.Web/Pages/Stocks/Details.cshtml:160-216`。

驗收：同一個股能直接看到 ROCE 是否符合設定、有哪些風險待查；提高其他比率分數不會消除風險提醒。

## 2. 用既有七年資料判斷持續性，並解釋 ROCE 變化

已有七年趨勢，但 `ScreenAsync` 實際選一個年度進行判斷。建議增加近五年 ROCE 中位數、達到使用者門檻的年數，以及有效年度／應有年度；缺年應另列，不能只把完整年度重新縮小分母後稱為通過。

只要沿用同期間及同一資本口徑，即可將目前 ROCE 拆成：

`營業利益率 × 投入資本週轉率 = (營業利益 ÷ 營收) × (營收 ÷ 投入資本)`

這個分解用於說明變化，不再另加一項評分。畫面可回答：營業利益增加、資本擴張，還是投入資本縮小？目前分母是期末總資產減流動負債；若日後增加平均投入資本版本，須另列名稱、取得期初資料，不能無聲取代既有公式。含利息收入 ROCE 維持補充角色。

ACCA 指出，ROCE 變化應搭配利潤率、資本週轉及資產購置／處分理解，資產購置時點亦會影響單年比較。[財報解讀說明](https://www.accaglobal.com/gb/en/student/exam-support-resources/fundamentals-exams-study-resources/f7/technical-articles/performance-appraisal.html)

依據：`RoceTool.Core/Calculators.cs:10-37`；`RoceTool.Infrastructure/StockAnalysisService.cs:182-209`；`RoceTool.Web/Pages/Stocks/Details.cshtml:225-247`。

驗收：單年突升與多年維持高 ROCE 的測試資料呈現不同持續性摘要；缺一年時清楚顯示缺漏。五年、中位數與達標要求均為待驗證的產品設定，不宣稱能保證投資報酬。

## 3. 把現金流變成必要核對，保留計算限制

既有七年 FCF、FCF／股、中位數和跳動提醒可直接沿用。主畫面先摘要多年營業現金流、資本支出與 FCF 的正負及累計，展開才看每股數字。FCF 為負時分開查看營業現金流與投資支出，不能直接認定公司品質不佳。

本專案的 FCF 是 `營業現金流 − |PPE 資本支出|`，尚未扣除無形資產支出，應繼續標示為 FCF_PPE；沒有正式股數時用淨利／EPS 推估，須核對兩者的歸屬口徑，不能與正式揭露股數同等呈現。

現行核對欄在 `CashFlowReviewNote` 回傳 null 時顯示 OK，但 null 也可能來自無前一年或缺值。建議拆成「未觸發跳動提醒／資料不足／需人工核對」，不能把未觸發規則等同於資料已核實。

損益與營業現金流本來就需要調整非現金項目及應計項目；營運、投資、融資現金流也有不同意義。[IFRS IAS 7](https://www.ifrs.org/issued-standards/list-of-standards/ias-7-statement-of-cash-flows/)

依據：`RoceTool.Core/Calculators.cs:7-8,77-130`；`RoceTool.Web/Pages/Stocks/Details.cshtml:251-303`。

驗收：缺現金流、缺前一年、前期為零、推估股數及大額資本支出，都能顯示各自狀態；不補零、不自動判為通過。

## 4. 公司品質與價格評估分開

既有最新官方 PE、各年年末股價／EPS 的靜態 PE、歷史 PE 中位數與 TTM EPS。年度價格透過 `/price-data` 非同步載入，是既有功能。

建議主價格區標示現價日期、EPS 起訖期間與估值口徑；確認連續四季後再提供現價／TTM EPS。歷史年末 PE 分布改稱歷史參考，不能直接把中位數命名為合理價。EPS 不為正或資料缺漏時保留不可計算狀態。

若加入價格情境，以明示的獲利假設與 PE 範圍計算，保留假設來源和修改日期；歷史便宜程度本身不保證未來報酬。均線與高點回落適合放補充觀察，不參與基本面品質判定。

依據：`RoceTool.Web/Pages/Stocks/Details.cshtml:52-108,144-227,334-388`；`RoceTool.Web/Program.cs:105-137`；`RoceTool.Web/wwwroot/js/site.js:303-329`。

驗收：歷史年度 PE 仍用當年末價格；最新官方 PE、自算 TTM PE、價格情境各有獨立標籤，價格變動不改變公司品質判斷。

## 5. 先處理可比性和缺資料，再調整篩選策略

以下為程式碼確認的優先缺口；未盤點本機資料中有多少公司實際受到影響：

| 項目 | 現行行為 | 建議 |
| --- | --- | --- |
| 季報與年度 | 未年化 YTD 套用年度評分，再顯示與年度差分 | 移除跨期間差分，改同年累計期間的去年同期比較；完整 TTM 指標另定義 |
| 同業年度 | Screen 未指定年度時各取最新年，再一起排名；個股同業比較固定選定年度 | 預設同一完整年度，過舊／缺年公司另列待更新 |
| 缺資料總分 | 可用權重重配後仍可能滿分；篩選預設 100% 覆蓋已有保護 | 個股摘要也以「可判讀／資料不足」區分；覆蓋率僅代表評分欄位，不代表多年或來源完整 |
| TTM EPS | 取最新四筆可還原的單季 EPS，僅檢查四筆和非空值 | 驗證四個相鄰季度及最新報告期間；缺季時不能拿更舊季度補成完整 TTM |
| 同規模排名 | 依投入資本三等分，可能產生 1／1 的名次 | 標明樣本數；不足時只呈現數值，不給有意義的相對排名結論 |
| 財報來源 | 依指定來源、ROCE 完整度、現金流完整度、來源優先與取得時間選整筆 | 展示選源理由；重大數值差異另標待核對，完整不代表已驗證正確 |

依據：`StockAnalysisService.cs:123-220,373-417,463-485`；`DomainModels.cs:156-195`；`ScoreEngineTests.cs:16-31`；`Details.cshtml:338-350`。以上短檔名分別位於 `RoceTool.Infrastructure`、`RoceTool.Core`、`RoceTool.Tests` 及 `RoceTool.Web/Pages/Stocks`。

## 建議落地順序

1. 修正季／年差分、TTM 連續性、同業混年與缺資料狀態。
2. 建立 ROCE 核心摘要：多年持續性、現金流核對、獨立風險提醒。
3. 整理價格區的期間與情境，再檢驗新篩選條件的影響。

驗證新篩選方法時，應比較原本單年方法與新方法的入選／排除原因。若評估歷史報酬，需另補當時可取得的財報公告日期、歷史股票母體及還原權息價格，避免把後來資訊帶回當時；現有七年圖表不能直接當作策略有效性的證明。

目前 Core／Infrastructure／Web 分層可沿用。新增多年摘要與資料狀態時，把純計算放 Core，來源及期間選擇留在 Infrastructure，Web 負責呈現即可，無需為這些改善更換技術架構。

## 產品實作建議：分階段調整

採漸進方式；第一階段先修正會讓使用者看錯資料的問題，再調整主畫面，最後才評估擴大候選範圍。每階段可以獨立檢視與回復。

### 第一階段：先讓資料結論站得住腳

- 個股報表顯示「可判讀／待補資料／期間不可比較」，資料不足時不要讓高分看起來等同完整判斷。
- 年報做同年比較；季報只同上一年相同累計期間比較，拿掉直接顯示 YTD 分數與全年差幾分的方式。
- TTM EPS 要檢查四個相鄰季度；缺季時顯示缺漏，不能以更早季度補成完整 TTM。
- 現金流檢查拆成「未觸發跳動提醒／資料不足／需要核對」。保留 PPE-only 定義及推估股數標籤。
- 同業排名顯示年份與樣本數；不同年份或太少樣本時不做顯著名次結論。

驗收重點：缺來源、缺欄、跨期間、缺季、無前期現金流等案例都會顯示正確狀態；沒有資料的值仍是缺值，不會補 0。

### 第二階段：把個股頁面整理成 ROCE 核心閱讀順序

首頁摘要依序呈現：資料狀態、最新完整年度 ROCE 與多年摘要、現金流核對、獨立風險提醒、價格參考。總分、技術線及其他比率留在補充區。新增多年摘要時同時顯示有效年數與缺年；不要先固定未經驗證的達標年數。

營業利益率與資本週轉用來解釋 ROCE 升降，不再各加一個投資總分。負債、流動比率以產業背景和歷史趨勢呈現風險，避免單一跨產業門檻決定結果。

驗收重點：第一次打開個股頁即可回答「ROCE 有多好、持續多久、現金流是否支持、有哪些待查風險」，逐項看到數字期間、來源及缺漏狀態。

### 第三階段：嚴格篩選與例外研究分開

保留一個名稱明確的「ROCE 條件符合」清單，仍依使用者設定的完整年度及門檻判斷。另設「例外研究／外部候選」檢視，供人工放入符合能力圈但目前沒過 ROCE／分數條件的公司，逐一看未通過原因、年度趨勢和當時價格。

例外名單是研究佇列，不代表建議買進、不改寫嚴格清單，也不把門檻悄悄降低。起初沿用人工輸入的外部標的功能即可；等其他 AI 的案例研究完成後，再決定是否增設少量明確的例外條件。必須保留每家公司「通過／未通過哪條」的理由。

對 Apple／NVIDIA 這類回顧案例，產品應能分辨四種結果：財報指標排除、其他評分排除、通過基本面但估值或買入時機不符、期間／資料不足而無法判斷。現在已有使用者自訂外部名單驗證流程，這個新增檢視不必先做自動選股。

驗收重點：同一公司能在兩條檢視分開顯示；加入例外研究清單不會自動變更篩選條件或加入正式觀察／持倉；每種排除都有可說明的原因。

### 第四階段：補上舞弊檢查、價格假設及選股表現的邊界

用「異常待查」呈現現金轉換、收入與利潤差異、來源間差異、重大年度跳動、來源日期；避免程式直接宣稱報表造假。若將來要查應收款、存貨或關係人細項，先確認標準化資料及可靠來源是否存在；目前模型不足以做完整舞弊風險偵測。

估值區分官方 PE、用已公告近四季 EPS 自算的 PE、歷史年度 PE 與使用者手動的獲利／PE 情境。每個數值標示財報期間、公告日、價格日和假設；把價格回落提醒留作提醒，不當作基本面或合理價結論。

選股績效要等公告日期歷史資料、下市公司、公司行動與股利資料齊備後再做；尚未定義買賣和持有規則之前，不能將篩選名單的歷史走勢稱作投資策略績效。產品上只先記錄候選進出條件和使用者判斷，之後才考慮持倉損益工具。

## 一個建議的最小首版

1. 修正季度比較、TTM 連續性與「OK／資料不足」狀態。
2. Screen 統一年份，顯示每家公司實際採用的年度、資料完整度和篩選理由。
3. 個股頁改以完整年度 ROCE 和七年趨勢為主，把現金流待核對、品質分數及估值分區。
4. 保留目前人工外部名單驗證，作為能力圈外研究清單；不自動降低既有門檻。
5. 以 Apple、NVIDIA 及不同產業／成功與失敗對照個案，先手動核對「被哪條規則排除」，再決定新增例外條件。

這個首版不必加很多指標，也不必先建立完整回測系統。關鍵是讓它說清楚「為何入選、為何排除、哪裡資料不夠」，同時保留探索其他機會的位置。
